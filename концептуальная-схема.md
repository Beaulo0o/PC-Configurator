# Концептуальная схема данных конфигуратора ПК

Концептуальная модель описывает проектируемую структуру данных клиент-серверного конфигуратора. Она охватывает каталог, сохранение сборок, сравнение цен и проверку совместимости. Схема представлена в трёх частях. «Комплектующее» связывает каталог со спецификациями, а «Спецификация материнской платы» связывает параметры платформы с данными накопителей.

В нотации Crow’s Foot `||` означает «ровно один», `o|` — «ноль или один», `o{` — «ноль или много», `|{` — «один или много». Обозначение на конце линии показывает, сколько экземпляров этой сущности может соответствовать одному экземпляру на другом конце.

## 1. Пользователи, сборки и каталог

```mermaid
erDiagram
    ROLE["Роль"]
    USER["Пользователь"]
    BUILD["Сборка"]
    ITEM["Позиция сборки"]
    COMPONENT["Комплектующее"]
    COMMENT["Комментарий"]
    CATEGORY["Категория"]
    BRAND["Производитель"]
    OFFER["Ценовое предложение"]
    SOURCE["Источник цен"]
    VALIDATION["Результат проверки"]
    MESSAGE["Сообщение проверки"]

    ROLE ||..o{ USER : "определяет права"
    USER ||..o{ BUILD : "владеет"
    BUILD ||--|{ ITEM : "содержит"
    COMPONENT ||--o{ ITEM : "выбрано в"
    USER ||..o{ COMMENT : "пишет"
    BUILD ||..o{ COMMENT : "содержит"
    CATEGORY ||..o{ COMPONENT : "группирует"
    BRAND ||..o{ COMPONENT : "выпускает"
    COMPONENT ||--o{ OFFER : "имеет"
    SOURCE ||--o{ OFFER : "публикует"
    BUILD ||--o| VALIDATION : "имеет"
    VALIDATION ||--o{ MESSAGE : "содержит"
```

| Сущность | Назначение и основные сведения |
|---|---|
| Роль | Определяет права обычного пользователя или администратора. У каждого пользователя ровно одна роль. |
| Пользователь | Учётная запись с логином и признаком блокировки. Может владеть несколькими сборками. |
| Сборка | Именованная конфигурация одного пользователя. Пользователь может сохранить неполную или несовместимую сборку, если в ней выбрана хотя бы одна деталь. |
| Позиция сборки | Выбор одного комплектующего в одной сборке. Содержит количество единиц каталожной позиции. |
| Комментарий | Сообщение к одной сборке с одним автором. Писать могут владелец сборки и администратор. |
| Категория | Тип комплектующего, например процессор или видеокарта. Категория определяет, какую спецификацию получает карточка. |
| Производитель | Справочник брендов комплектующих. У каждой карточки указан один производитель. |
| Комплектующее | Карточка конкретной модели с базовой ценой, оценкой потребления и состоянием в каталоге. |
| Источник цен | Площадка, используемая для сравнения цен. Для демонстрации предложения могут формироваться на синтетических данных. |
| Ценовое предложение | Текущие цена и наличие одного комплектующего у одного источника. У одной пары «комплектующее — источник» не более одного предложения. |
| Результат проверки | Последняя сохранённая проверка сборки с отметкой времени. При сохранении через приложение результат обновляется, при открытии сервер проверяет сборку заново по актуальным данным. |
| Сообщение проверки | Ошибка или предупреждение, сформированное конкретным правилом. Успешная проверка может иметь пустой список сообщений. |

### Как связаны пользователь и комплектующее

**Пользователь 1 → 0..N Сборка 1 → 1..N Позиция сборки 0..N ← 1 Комплектующее.**

Пользователь может выбирать разные комплектующие в разных сборках, и одну модель могут выбирать разные пользователи. Связь «пользователь — комплектующее» прослеживается через владельца сборки и её состав. Ассоциативная сущность «Позиция сборки» разрешает M:N между сборкой и комплектующим двумя связями 1:N. Количество относится к позиции: один пользователь может указать два экземпляра SSD в рабочей сборке и один экземпляр той же модели в домашней.

Прямые связи M:N на диаграммах отсутствуют. Предложение связывает комплектующее и источник цен. Комментарий фиксирует отдельное действие автора в конкретной сборке, поэтому один автор может оставить в ней несколько сообщений.

## 2. Спецификации и параметры установки

```mermaid
erDiagram
    COMPONENT["Комплектующее"]
    CPU["Спецификация процессора"]
    BOARD["Спецификация материнской платы"]
    RAM["Спецификация оперативной памяти"]
    GPU["Спецификация видеокарты"]
    PSU["Спецификация блока питания"]
    CASE["Спецификация корпуса"]
    COOLER["Спецификация охлаждения"]
    SOCKET["Сокет"]
    COOLER_SOCKET["Поддерживаемый сокет охлаждения"]
    MEMORY["Тип памяти"]
    FORM["Форм-фактор платы"]
    CASE_FORM["Поддерживаемый форм-фактор корпуса"]

    COMPONENT ||--o| CPU : "имеет"
    COMPONENT ||--o| BOARD : "имеет"
    COMPONENT ||--o| RAM : "имеет"
    COMPONENT ||--o| GPU : "имеет"
    COMPONENT ||--o| PSU : "имеет"
    COMPONENT ||--o| CASE : "имеет"
    COMPONENT ||--o| COOLER : "имеет"
    SOCKET o|..o{ CPU : "используется в"
    SOCKET o|..o{ BOARD : "используется на"
    SOCKET ||--o{ COOLER_SOCKET : "указан в"
    COOLER ||--o{ COOLER_SOCKET : "поддерживает"
    MEMORY o|..o{ RAM : "характеризует"
    MEMORY o|..o{ BOARD : "поддерживается платой"
    FORM o|..o{ BOARD : "задаёт формат"
    FORM ||--o{ CASE_FORM : "указан в"
    CASE ||--o{ CASE_FORM : "поддерживает"
```

Связь карточки с каждой спецификацией имеет кратность 1 : 0..1. Для каждой карточки в целом требуется ровно одна спецификация, соответствующая её категории. Спецификация может существовать при неизвестных отдельных характеристиках. Например, у видеокарты может быть неизвестна длина.

| Категория | Характеристики для подбора и проверки |
|---|---|
| Процессор | Сокет, число ядер и потоков. |
| Материнская плата | Сокет, тип памяти, число слотов и максимальный объём памяти, форм-фактор, группы разъёмов накопителей. |
| Оперативная память | Тип памяти, объём и число модулей в одной продаваемой позиции. |
| Видеокарта | Длина, объём видеопамяти. |
| Блок питания | Номинальная выходная мощность. |
| Корпус | Допустимая длина видеокарты, допустимая высота воздушного кулера, поддерживаемые форм-факторы плат. |
| Система охлаждения | Тип охлаждения, высота воздушного кулера, поддерживаемые сокеты. |
| Накопитель | Ёмкость и профиль подключения, показанный на следующей диаграмме. |

Сокеты, типы памяти и форм-факторы задаются справочниками. Корпус может поддерживать несколько форм-факторов, а кулер — несколько сокетов. Поэтому поддержку описывают отдельные строки для каждой пары «корпус — форм-фактор» и «охлаждение — сокет». Для списков поддержки предусмотрена отметка о полноте: отсутствие строки в подтверждённом списке означает отсутствие поддержки, отсутствие подтверждённого списка означает недостаток данных.

## 3. Подключение накопителей

```mermaid
erDiagram
    COMPONENT["Комплектующее"]
    DRIVE["Спецификация накопителя"]
    CONNECTION["Профиль подключения накопителя"]
    BOARD["Спецификация материнской платы"]
    BOARD_PORT["Группа разъёмов платы"]
    PORT["Тип разъёма"]
    PORT_SUPPORT["Поддержка профиля разъёмом"]

    COMPONENT ||--o| DRIVE : "имеет"
    CONNECTION o|..o{ DRIVE : "характеризует"
    BOARD ||--o{ BOARD_PORT : "имеет"
    PORT ||--o{ BOARD_PORT : "определяет возможности"
    PORT ||--|{ PORT_SUPPORT : "имеет"
    CONNECTION ||--o{ PORT_SUPPORT : "поддерживается через"
```

Профиль задаёт конструктив и способ подключения накопителя, например кабельный SATA, M.2 SATA или M.2 PCIe/NVMe. Группа разъёмов платы задаёт количество одинаковых физических разъёмов. Один тип разъёма может принимать несколько профилей. Например, один комбинированный слот M.2 поддерживает SATA и NVMe, но одновременно вмещает только один накопитель. Отдельные строки поддержки описывают возможности слота, а количество задаётся один раз в группе разъёмов платы.

## 4. Правила предметной области

- **Состав сборки.** Для пары «сборка — комплектующее» существует одна позиция с положительным количеством. Если единица товара — комплект из двух модулей ОЗУ, то две единицы товара занимают четыре слота. Выбор нескольких процессоров, плат, блоков питания или корпусов фиксируется как ошибка проверки. Такую конфигурацию можно сохранить для дальнейшего редактирования.
- **Наличие и цены.** Администратор задаёт состояние карточки в каталоге. Наличие у каждого источника хранится в его предложении. Недоступную или снятую с ассортимента карточку нельзя добавить в новую позицию. В сохранённой сборке ссылка сохраняется, и сервер показывает предупреждение. Базовая стоимость рассчитывается по ценам каталога, а предложения используются для сравнения.
- **Проверка совместимости.** Сервер сравнивает сокеты, тип и объём ОЗУ, число модулей и слотов, поддерживаемый форм-фактор, габариты видеокарты и воздушного кулера, доступные подключения накопителей и мощность БП. Неизвестная характеристика даёт предупреждение по соответствующему правилу. Ошибки и предупреждения сохраняются вместе с последним результатом проверки.
